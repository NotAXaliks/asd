# NEON ARENA — демо для Дня Профессионала («Программные решения для бизнеса»)

Прототип системы администратора компьютерного клуба. **Только десктоп** (мобилка отменена).
Приложение крутится на большом экране у стенда в авто-режиме; среднее время просмотра ~40 секунд,
поэтому всё должно быть понятно с первого взгляда: зал живёт, деньги считаются, цифры для владельца.

Принципы:
- Главное — красиво показать, а не сделать «правильно». Упрощения и подгонка данных допустимы.
- Каждая деталь связана с бизнесом: выручка, загрузка, средний чек, балансы клиентов, окупаемость.
- Спокойный «рабочий» дизайн: без неона, свечения, градиентов и эмодзи (иначе выглядит как сгенерированное).

## Стек и окружение

| Что | Решение |
|---|---|
| UI | Avalonia 12.0.2, .NET 10, тёмная тема, CommunityToolkit.Mvvm 8.4.2 |
| БД | PostgreSQL 18 в docker-контейнере `postgres`, порт 40001, база `proday` |
| Доступ | EF Core напрямую (Npgsql.EntityFrameworkCore.PostgreSQL 10.0.3 + EFCore.NamingConventions), без API и миграций |
| Схема | `database.sql` пишется руками, заливка: `docker exec -i postgres psql -U xaliks -d proday -v ON_ERROR_STOP=1 < database.sql` |
| Графики | самописные (ItemsControl + Border), без библиотек |

Строка подключения — константа `ClubDb.Conn` в `Club.Core/Db.cs`.
В базе `proday` лежат чужие таблицы (`devices`, `events`, `rooms`, …) — не трогать.

## База данных

Таблицы: `games` (6 игр), `pcs` (9 ПК: PC-01…04, 07…09 Standard 150 ₽/ч; PC-05, 06 VIP 250 ₽/ч),
`sessions`, `payments` (session / extend / bar), `audit_log`, `players` (ник + баланс), `topups` (пополнения с бонусом).

- `expire_sessions()` — атомарно закрывает истёкшие сессии, освобождает ПК, пишет «время … истекло». Десктоп зовёт каждую секунду.
- `reset_demo()` — генерирует историю относительно `now()`:
  - 7 дней истории в окне «смены» (последние ~12 ч каждого дня), сессии 30–180 мин, бар, пополнения;
  - последние 12 минут — короткие сессии по 10–20 с (как в авто-режиме), чтобы поминутный график был заполнен сразу;
  - живое состояние: 4 занятых ПК, сессии заканчиваются через 6–17 секунд; PC-04 выключен.
- Кнопка «Сброс демо» на экране вызывает `reset_demo()`.

## Экран (MainWindow)

1. **Шапка**: название, «онлайн», часы, тумблер «Авто-режим», «Сброс демо». F11 — полный экран.
2. **KPI**: выручка за смену (count-up и «+N ₽» при каждом платеже, сравнение со средней сменой),
   прогноз на месяц, загрузка зала и потери от простоя, средний чек, деньги на балансах клиентов,
   окупаемость клуба (вложено 1,1 млн ₽, прогресс, сколько месяцев осталось).
3. **Зал**: 9 тайлов 3×3. Цветная полоска слева: зелёный — свободен, красный — занят, жёлтый — заканчивается,
   серый — выключен. У занятого: игра, ник, таймер, прогресс. Внизу — выручка ПК за смену, «лидер смены».
   Клик по тайлу — меню: включить/выключить, сессия 1 час / 30 мин, продлить, завершить.
4. **Журнал событий**: цветная точка, время, текст. Новые строки подсвечиваются.
5. **Графики**: выручка по минутам за 12 минут / по дням за неделю; выручка по играм; структура выручки (игры / бар).

## Ускоренное время (демо)

- Любая сессия длится **10–20 реальных секунд** (`Biz.RealDuration`), продление +10 с (`Biz.RealExtend`).
- Авто-режим (`ClubService.SimulateStepAsync`, ход раз в 2 с):
  - 55% — садятся 1–2 гостя (тариф «15 мин» 40/60 ₽, иногда «30 мин»), обычно занято 5–7 ПК из 9;
  - 5% — покупка в баре, 5% — смена игры, 2% — пополнение баланса, 3% — ранний уход,
    6% — включение выключенного ПК, 2% — выключение свободного.
- Поминутный график рассчитан на темп авто-режима (~1–1,5 тыс. ₽/мин) — столбики остаются ровными сколько угодно долго.

Известное ограничение: при долгой работе в авто-режиме накопительные цифры (выручка за смену, «к средней смене»,
столбик «сегодня» в недельном графике, окупаемость) растут быстрее реального клуба. Лечится кнопкой «Сброс демо».

## Грабли

- Перед сборкой закрыть приложение: `taskkill //IM ProDay.exe //F`, иначе exe заблокирован.
- Собирать `ProDay/ProDay.csproj`, а не весь sln.
- Compiled bindings включены: у каждого `DataTemplate` нужен `x:DataType`.
- В `timestamptz` писать только UTC (`DateTime.UtcNow`).
- После ручной перезаливки `database.sql` перезапустить приложение (id журнала начинаются заново).
- Скриншот окна для проверки — через PrintWindow с `SetProcessDPIAware` (экран масштабирован 125%).
